## In plain words
Microsoft Azure Speech is Microsoft's service that turns speech into text and text into speech. JARVIS can use its free tier on phone calls, to hear what the other person says and to speak JARVIS's side, in English and most major Indian languages (`src/jarvis/calls/speech/build.py:build_speech`). It is off until you set an Azure free-tier key, `azure_speech_key`; without one it is simply not offered. The free tier cannot bill, so it costs nothing and stops once its monthly allowance is used. What goes to Microsoft: each short clip of the other person's voice with the language to hear it in, and the text of each line JARVIS says, sent to the Azure region set for it. A language uses Azure on a call only after Azure passed JARVIS's language check for it; before English has been checked, English calls use Google, or Azure when Google is not set up.

## Example (made up)
You set an Azure key, run the language check for Hindi, and Azure passes at ₹0. At 11:10 JARVIS calls a clinic in Hindi to book an appointment. The receptionist speaks for about 70 seconds in all, in 14 short clips, and JARVIS says 10 lines of 900 characters in all. The month's Azure counters move from 2,300 to 2,377 seconds of hearing, as each clip is rounded up to whole seconds, and from 41,000 to 42,760 characters, as each line counts with its bit of markup. The call's speech costs ₹0.

## How it works
`build_speech` builds Azure's hearing and voice only when `azure_speech_key` is set, at the region in `azure_speech_region` ({{fact:settings.azure_speech_region}} by default); otherwise the language table lists Azure as not set up, with that reason (`src/jarvis/calls/speech/build.py:SpeechOptions`). `_SpeechFactory` builds these options for each call and for the language check, on one connection that waits at most {{fact:src/jarvis/api/r18_wiring.py:SPEECH_TIMEOUT_S}} seconds and follows no redirect (`src/jarvis/api/r18_wiring.py:_build`). Hearing sends one clip at a time as a WAV with the language to hear it in; Azure's short-audio service has no language detection, so on a call with several languages a clip JARVIS is unsure of is heard in each language in turn (`build_speech`). The voice sends the line's text with that language's stock male voice and gets the sound back in JARVIS's own call format (`build_speech`). The key travels only in Azure's key header and is never logged (`azure_speech_key`). `speech_prices` gives Azure a price of ₹0 from `voice_price_azure_f0_inr_per_hour` and `voice_price_azure_f0_inr_per_m_chars`, which the settings hold at nothing, and marks it as an option that cannot bill (`src/jarvis/calls/prices.py:SpeechPrice`). Its free allowance is counted for the whole server: `voice_azure_f0_stt_free_seconds` ({{fact:settings.voice_azure_f0_stt_free_seconds}} seconds of hearing a month) and `voice_azure_f0_tts_free_chars` ({{fact:settings.voice_azure_f0_tts_free_chars}} characters of voice). Each request holds its units on that counter first, whole seconds for a clip and every character of a voice request, and gives them back when Azure surely did not count it, so two calls never both take the last free seconds (`build_speech`). `_cards` estimates a call card with these prices, so a call on Azure is estimated at ₹0 (`src/jarvis/api/r18_wiring.py:_cards`). `finish_r18` tells Calls → Settings whether Azure is ready or off (`src/jarvis/api/r18_wiring.py:finish_r18`).

## What it costs
₹0: the free tier cannot bill, so JARVIS prices it at nothing and it never adds to your monthly spend (`src/jarvis/calls/prices.py:speech_prices`). Its monthly allowance is {{fact:settings.voice_azure_f0_stt_free_seconds}} seconds of the other person's speech and {{fact:settings.voice_azure_f0_tts_free_chars}} characters of JARVIS's voice for the whole server. Each clip counts as whole seconds, and every spoken line counts with the few characters of markup around it. On a call with more than one language, a clip JARVIS is unsure of is heard once in each language, which uses the free seconds faster.

## When it fails
Without a key, Azure is not offered, and the language table says no Azure free-tier key is set (`build_speech`). Once the month's allowance is used up, Azure stops before sending anything and says so plainly, and Azure's own quota refusal is read the same way, never as a bad key (`voice_azure_f0_stt_free_seconds`). A refused key shows Azure as unavailable. A clip longer than Azure's short-audio limit, or a line too long to speak, is refused before it is sent. If Azure fails during a call, JARVIS does not move that language to an option it did not pass; that line fails instead. A busy Azure is retried only where it surely did not process the request, so nothing is counted twice.
