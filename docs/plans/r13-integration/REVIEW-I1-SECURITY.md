## Checked and fine

- Photos and prints: private is refused from the RECORD inside the transaction (`photos.py:_keepable`, `Prints.save`, `PhotoVault.save`); marking private drops both in the same commit (`drop_ops`); tagging re-reads the record (`_allowed`: private, or a private-by-default type, refused); backup with photos reads docs from `p.photos` only (a private piece has none); restore returns photos and prints only with non-private pieces it adds (`_photo_ops`, `_record`), never merging a private piece's prints (`allowed`); photo and print blobs are sealed under a separate purpose (`wardrobe_photos`) with the id in the AAD; GET photo checks `owner`; `frame_size` can't loop; JPEG cleaned by structure, never decoded.
- Privacy rows: five rows, `row_of` fails closed for an unknown name or row (all server rows unavailable, nothing deleted, `UnsortedData`), the photos export is a count only, the device row refuses delete. (Gap: M1.)
- Untrusted content: model view is `redact.model_view` (private = slot and state, labels and places fenced by `say`, unverified fields never shown); `vouch` only for typed labels; `_own_words` refuses label, set label and a place by name on a tainted OR spoken round before any card, for add, edit and places; edit and add drop `label` on `origin == "outside"`; places add/rename refused outside; write tools take piece ids; calendar titles are matched in memory, never stored, and `fields=` names only what he allowed; OCR is parsed to fixed fields, `read=True` unverified; foreign QR is only counted; tag answers are filtered to fixed lists (`suggestion`), the prompt says text in the picture is data; alerts are fixed words (`texts.py`), private pieces read "a private basic"; no shop, label or place in any alert.
- No-AI phrases (`offline/phrases_r13.py`): anchored, whole-message, bounded (400 chars), `TakeCall` takes only a string id from the find step, a name that fits several stops the turn; a spoken `put` is refused by `_own_words`; typed `put` is the owner's own words.
- Confirm before commit: `NO_BULK_TOOLS` = drill, `wardrobe_merge`, `wardrobe_retire`, `outfit_plan` (`guardrails.py:71`); merge and retire are `ask_when` always; remove is undoable with a 30-day bin; whole-plan release is `ask_when`; `laundry_send_out` records only (no order, call or message) and refuses a send in a round that read others' words; panel changes go through `gateway.execute` (`/v1/wardrobe/tools/{tool}`, `TOOL_OWNER` only, a card waits in a conversation of his own, another user's `session_id` is ignored). Settings is a route, never a tool. Direct routes (scan, labels, photos, fingerprints, settings, restore) are owner-only, rate-limited and `no-store`; scan refuses cards-only kinds, laundry kinds and the camera source.
- Money: AI tagging default False (`model.py:303`); cap default 30, 0 = never; reserve-then-settle in ONE `rewrite` transaction, refund on `CantLook` and other exceptions; `BrainEyes` checks No-AI, a seeing brain, `Billing.ensure_allowed` and records the cost; no vendor SDK outside `jarvis.llm` (imports are `jarvis.llm.*` and `jarvis.picture.eyes`). (Gaps: L1, L4.)
- Auth and guests: all wardrobe, laundry and outfits routers carry `require_auth` (CSRF on session writes) and `current_user`; the guest lock is an allow-list (`book_lock.ALLOWED`) with no R13 route in it, so a Build Book guest or a show-locked owner browser gets 423 on every wardrobe route; the R13 diff does not touch passkey, fresh-sign-in, the 45-minute or 10-minute rules. Telegram: `wardrobe_*`, `laundry_*`, `outfit_*`, `wear_*` join the personal-reads group (default off); PERSONAL_REFUSAL names the wardrobe.
- Logs and audit: gateway failure logs `{"tool", "error": type(exc).__name__}` only (`gateway.py:528`); every `log.*` under `wardrobe/` and the wiring logs a class name, counts or a collection name; `hide_input_in_errors` on C's sealed models; settings audit lines carry names that moved, not values; calendar reads write a kind-only audit line; the needles eval searches logs, audit, cards, sessions, tool results and backup, all green by the report.
- Integrity: backup v2 (head in clear with `fid`, per-line AAD with the line number, line 1's AAD includes SHA-256 of the head, `end` line counts lines, uid in AAD); restore opens every line before writing, token = MAC over uid, file digest, expiry, `empty` and the purge count (`restore.py:_token`), compared in constant time, stateless; current records win, settings and the ₹ counter are never restored; chunked and rerunnable; `transact()` runs `fn` and the review writer inside one transaction so holds and their entries commit together; index sealed with `wardrobe` purpose and uid AAD; an unreadable index is never overwritten.
- Public repo: grep of the whole R13 diff (code, fixtures, eval data, docs) for personal names, real places, phone numbers, hostnames, keys, chat links found none; only `example.com` addresses and public API hosts (Google Calendar, Open-Meteo). `evals/r13/report.json` holds ids and pass flags only. (Not R13: a creator name "the owner's full name" appears in `tests/test_book_api.py` and the R6.2 tests, already on main; worth a one-line scrub by the Workshop.)

## Verdict

Fix first, but only M1 to M3 (small, local changes); nothing CRITICAL or HIGH. M1 (erasure when the key is gone or changed, and a false "Nothing kept yet") and M2 (merge drops privacy) are real privacy gaps; M3 needs a one-run probe to confirm. L1 to L5 can ship with a ticket.
