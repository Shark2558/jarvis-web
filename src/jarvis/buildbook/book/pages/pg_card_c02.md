## In plain words
This is JARVIS's front door: the server that the console, the phone app and the terminal all talk to. It lets in only the Google accounts you listed as owners, plus a secret token for the terminal and the tests, and it works out who you are from that sign-in, never from what a page claims. It limits how fast any one client may call it and how big a request may be, so a flood or a huge upload doesn't bring it down (`src/jarvis/api/ratelimit.py`, `src/jarvis/api/body.py`). When something goes wrong, you get a short plain answer, never a programmer's error dump.

## Example (made up)
At 7:00 you open JARVIS on a new phone. It has no cookie yet, so the console sends you to Google; you sign in with your own account, and JARVIS sets a signed cookie for the next 12 hours. At 13:00 a script on a stranger's computer floods the server; after its first 120 requests in that minute it gets "too many requests" and a wait, while your chat carries on. That evening a friend tries the link with his own Google account and sees "This JARVIS belongs to someone else."

## How it works
`create_app` builds the one server in named steps: the core parts, each release's wiring, then the middleware, the error mapping and the routes (`src/jarvis/api/app.py`). `login` sends you to Google, and `callback` accepts only a verified address on `owner_emails`; any other account gets status 403 (`src/jarvis/api/auth.py`). The session cookie it then sets is signed, lasts {{fact:settings.session_cookie_max_age_s}} seconds from your last visit, and ends for good {{fact:src/jarvis/api/auth.py:SESSION_ABSOLUTE_MAX_S}} seconds after you signed in (`session_email`). `session_email` checks your address against the owner list on every request, so taking an address off the list signs that browser out at once. `require_auth` lets in that cookie or the terminal's bearer token, compared in constant time, and a browser's writes must carry a JARVIS header that another website is unable to add (`CSRFRejected`). `current_user` makes your user id from the sign-in, a short hash of your address, and a user id sent by a client is never read (`src/jarvis/api/identity.py`). A re-sign-in that a sensitive step asks for, such as opening the Build Book, counts as fresh for {{fact:src/jarvis/api/auth.py:FRESH_SIGN_IN_S}} seconds (`fresh_sign_in_left`). The Build Book's routes add their own gate on top: the console only, never a script with a token, and a live book session (`src/jarvis/api/book_gate.py`). The full book's own page, `GET /book/read`, is served with the console's headers and holds no data: it reads the book with the session's token kept in that tab (`src/jarvis/api/book_read.py`). A call's live socket opens only with the terminal's token, your sign-in from JARVIS's own page or a one-use ticket (`ws_owner`, `LiveTickets`); the call desk's socket needs its signed header first (`src/jarvis/api/calls_ws.py`). `RateLimiter` gives each client {{fact:settings.rate_limit_per_minute}} requests a minute on the API, sign-in and internal paths, keyed on the address the hosting itself adds, which a caller is unable to forge (`client_key`). `BodySizeLimit` refuses a request over {{fact:src/jarvis/api/body.py:MAX_BODY_BYTES}} bytes before reading it, with larger caps only for uploads (`src/jarvis/api/body.py`). Errors become a short answer with an error code, and an AI vendor's own words stay in the log (`friendly_llm_error`). Every answer carries the request's trace id and a no-sniff header, and the server publishes no list of its routes (`create_app`). `log_up` writes one "jarvis up" line naming which parts started, never a key or an address (`src/jarvis/api/startup_log.py`).

## What it costs
Nothing in JARVIS itself: the sign-in is Google's own, and the server runs inside Cloud Run's free allowance as the deploy sets it up. The size of that free allowance is Google's and is Unverified here.

## When it fails
A missing or wrong sign-in gets status 401, which brings back the console's sign-in gate (`require_auth`). A Google account that isn't an owner gets status 403 and "This JARVIS belongs to someone else." More requests than the limit get status 429 with a wait in seconds (`src/jarvis/api/ratelimit.py`). A body over the cap gets status 413. A Google sign-in that breaks halfway says "sign-in could not be completed; please try again" and logs only the kind of error (`callback`). Outside development, start-up stops on an unsafe setting, such as no API token (`create_app`).
