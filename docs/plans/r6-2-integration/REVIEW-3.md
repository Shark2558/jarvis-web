## Answers to the brief
1. Atomicity: reserve_units and release_units each do read and write inside one `Docs.transaction`. The in-memory store serialises with `_tx_lock` and applies ops only after fn returns, so an exception writes nothing. Firestore uses async_transactional behind a process lock plus optimistic retry, so it also holds across instances. A hold is "the count": there is no second record, so it cannot double count, and a normal settle (`_meter` with held) writes nothing more. Negative is impossible (`-min(units, used)`). Unreadable counter: `AllowanceUse.used` raises UsageUnreadable, so reserve fails closed as BudgetUnavailable and writes nothing (test at test_r62_book_listening.py:393 forces this). Release never raises and a failed release only keeps the count high. Double release: the paths are exclusive (unhold in _engine for not-billed VoiceUnavailable, and `_recognise` only unholds VoiceRejected, which _engine does not touch); I found no path that releases twice. A hold is never released after maybe_billed or CancelledError (those settle, count stays). The leaks are the missing-release paths in the MEDIUM row, never a wrong release.
   Old `ensure_free`: no remaining caller in src/ or tests/ (grep clean). Owner/priced path: `_gate` returns 0.0 after the unchanged `ensure_units_allowed`, `_meter` with held=0.0 falls through to the unchanged `record_units`, `_engine` adds only an `else: _unhold(held=0)` no-op. The R5 console voice (free_only=False default) behaves as before.
2. Rules: a guest's speak and hear are both `free_only=view.audience != "owner"`; never priced because the hold is the count and `_meter` returns before record_units. Owner confirmation for cost switching is untouched by this delta. Audit/logs: new log lines carry only the key, reason class name, chars and seconds; no text or secrets. FreeAllowanceUsed maps to the content-free "free_used" reason on both routes.
3. /show/script: unchanged server code; guests receive the same body as before (no cost, no owner data). Client calls it on a mic tap (skipped while recording, busy or syncing) and on tab-visible only when the questions panel is open; it is bounded by the 20/min limit and failures keep the current state. 401 expires the show correctly.
4. JS: L1 watchdog: halt() clears the previous dog, aborts after 3 s, finish() is idempotent via `cur !== me`, and a late onend after abort is ignored. cancel() leaves the dog timer, which then no-ops. L2 gen check before landed(): correct. L3 `V().stop()` plus hush stops reply and follow-up narration. Open issues are the two mic() rows above.
5. Tests: the concurrency test is a real race (different owners so the per-owner lock does not serialise, FakeSTT delay=0.02, asserts one Google call and counter == free_units). Under the old check-then-call both would pass, so it fails without the fix. Counter and failed-call tests would fail if the hold or unhold were removed (except for the untested VoiceBusy/TTS-rejected paths).
6. Limits: voice/service.py is 640 lines, meter.py 361, billing/service.py 506, Book JS max 390 (show), talk.js 366: all within limits. New functions are under 50 lines. No vendor SDK import added outside jarvis.llm.
